# 固定四班设计书

## 目标

在保留现有白班、夜班及其历史日报关联的前提下，将系统班次扩展为固定四班：

1. 网管早班
2. 白班
3. 夜班
4. 网管夜班

四个班次都使用现有完整财务日报，但不要求每天全部提交。网管班属于独立业务班次，不参与营业班之间的开始时间自动承接。

## 当前实现与问题

- `SetupService` 在 API 启动时把有效班次校准为固定的白班、夜班，并停用其他班次。
- 管理员设置页只能修改已有班次名称，系统没有新增班次的界面或 API。
- `DailyReport` 通过 `@@unique([reportDate, shiftId])` 保证同一业务日、同一班次只有一份日报。
- 网管首页、管理员补录、统计和导出已经根据有效 `Shift` 及 `sortOrder` 动态处理多个班次。
- 当前默认开始时间通过 `sortOrder` 查找相邻上一班。加入网管班后，如果继续使用相邻关系，会错误形成四班连续承接。

## 已确认的业务规则

### 固定班次

班次数量、名称和顺序全部固定：

| `sortOrder` | 名称 |
| ---: | --- |
| 1 | 网管早班 |
| 2 | 白班 |
| 3 | 夜班 |
| 4 | 网管夜班 |

管理员不能新增、删除、停用、改名或重新排序班次。

### 日报规则

- 四个班次使用相同的完整财务日报字段、金额计算和校验规则。
- 每个班次是否提交相互独立，不强制同一业务日达到四份日报。
- 同一业务日、同一班次仍只允许一份日报。
- 统计和导出只汇总实际提交的数据，并按固定四班顺序展示。

### 时间承接

展示顺序不代表时间承接关系。唯一的自动承接关系是：

`夜班 → 同一业务日的白班结束时间`

具体行为：

- 网管早班：不自动填写开始时间。
- 白班：不自动填写开始时间。
- 夜班：白班日报存在时，以白班结束时间作为默认开始时间；仍允许填报人手动修改。
- 网管夜班：不自动填写开始时间，也不承接网管早班。
- 白班日报不存在时，夜班开始时间保持未自动填写状态。

## 方案

采用“启动时声明式校准固定四班”的方案，不修改 Prisma 数据结构。

新增一个聚合班次业务常量与关系的后端规则模块，负责：

- 定义固定四班的名称和 `sortOrder`。
- 定义唯一的时间承接映射 `夜班 → 白班`。

`SetupService` 只负责把数据库状态校准到固定定义；`DailyReportsService` 只负责按照承接映射查找默认开始时间。显示顺序和时间关系不再由同一套隐式位置规则承担。

## 启动校准

API 模块初始化时，在数据库事务内执行幂等校准：

1. 读取现有班次，按 `sortOrder` 和 `id` 建立稳定顺序。
2. 对每个固定名称优先复用一个现有记录。
3. 复用记录时只修正 `sortOrder` 和 `active: true`，不更换 ID。
4. 固定班次不存在时创建对应记录。
5. 固定四班以外的记录以及同名重复记录设置为 `active: false`，不删除。
6. 任一步骤失败时回滚事务并让 API 启动失败，避免应用在部分校准状态下运行。

该流程保证：

- 现有白班、夜班 ID 及历史日报外键保持不变。
- 新增网管早班、网管夜班后，重复启动不会重复创建。
- 非固定班次仍保留在数据库中，其历史日报关联不会丢失。

## API 与界面

### API

- 保留 `GET /meta/shifts`，继续返回 `active: true` 的班次并按 `sortOrder` 排序。
- 删除 `PATCH /meta/shifts` 及对应 DTO，阻止通过接口修改固定配置。
- 已缓存旧前端若继续调用被删除的接口，将收到 404；这是固定班次契约下的预期行为。

### 管理员设置页

- 删除“班次名称”编辑区域及保存函数。
- 保留底钱和负责人设置，不改变相邻功能。

### 网管与管理员日报

- 网管首页自动显示四张班次卡片，并以“已提交数量 / 4”展示进度。
- 管理员补录与日报表单从 `GET /meta/shifts` 获取同一固定四班。
- 不增加“业务日完成”或“必须提交四班”的阻断逻辑。

### 统计与导出

- 沿用现有按 `shift.sortOrder` 的排序与按实际日报汇总的逻辑。
- 不为空缺班次生成零值日报或虚拟汇总项。

## 历史数据兼容

- 不修改 `DailyReport` 表结构。
- 不重写历史日报的 `shiftId`、`shiftNameSnapshot`、时间或金额。
- 原白班、夜班记录只调整当前主数据顺序和启用状态。
- 新增两个网管班可用于新日报和管理员补录；不会为历史日期自动生成日报。
- 被停用的非固定班次不再出现在新建日报选项中，但已有历史日报仍可通过原关联读取和导出。

## 异常处理

- 启动校准发生数据库异常时依赖事务回滚，并让模块初始化失败。
- 查询默认开始时间时，日期或班次参数无效、当前班次没有承接规则、来源班次不存在、来源日报不存在，均返回 `previousShiftEndMinute: null`。
- 日报创建和更新继续使用现有的有效班次校验、唯一性校验与错误文案。

## 测试与验收

### API 自动化测试

为 `apps/api` 增加 Vitest 开发依赖和测试脚本，不增加生产依赖。覆盖：

- 固定四班名称和顺序准确。
- 已有白班、夜班记录被复用且 ID 不变。
- 缺少的网管早班、网管夜班被创建。
- 重复执行校准不会重复创建班次。
- 额外班次和同名重复记录被停用而非删除。
- 只有夜班查询同一业务日白班的结束时间。
- 网管早班、白班、网管夜班均不查询上一班并返回空。
- 白班日报不存在时夜班返回空。
